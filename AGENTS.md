# Project documentation

Everything below this line is project-specific and **not** regenerated by `next dev` (only the block above is). Not every doc is relevant to every task — don't read a file outside its bucket below; it wastes context and some of them aren't meant for agents at all.

### Always read

Read these every session before writing code, regardless of the task — they govern how code gets generated and published:

- [`FOUNDATIONS.md`](./FOUNDATIONS.md) — code-level rules: file naming, folder structure, component/constant/util conventions, the `~` import alias. Read before creating, naming, or placing any file.
- [`CONTRIBUTION.md`](./CONTRIBUTION.md) — git workflow: branch naming, commit message format, PR process and evidence bar. Read before committing or opening a PR. (Uses [`.github/pull_request_template.md`](./.github/pull_request_template.md), populated via the `create-draft-pr` skill — don't fill it out by hand; no separate read needed.)

### Read only when relevant

- [`DESIGN.md`](./DESIGN.md) — visual design tokens: color, typography, spacing, radius, elevation. Read **only** when the task touches UI/styling or `components/ui/` (the design system). Skip it for non-visual work (logic, data, config, infra).
